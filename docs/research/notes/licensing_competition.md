# Licensing implications and competitive landscape: open-source embroidery file tools in EEganizer (closed-source SaaS)

Research date: 2026-10-10. This is not legal advice; points marked "counsel" need review by an IP/open-source lawyer before shipping.
Research environment note: gnu.org, wilcom.com and help.wilcom.com could not be fetched directly (proxy/DNS refusal). Points that rest on those sites come from search-result excerpts or secondary quotes and are marked as such. License files for the open-source projects were fetched directly from raw.githubusercontent.com and PyPI.

## Q1. License obligations (MIT, BSD, zlib, LGPL, GPL-2/3, AGPL) for server-only use, JS/WASM shipped to the browser, and calling GPL tools as a separate process; and what license each embroidery project actually uses

### Takeaway
pyembroidery and Ink/Stitch's fork pystitch use the MIT license. libembroidery and Embroidermodder use zlib. Both are safe to use server-side and in the browser if EEganizer keeps the copyright/permission notice (MIT) or does not misrepresent the code's origin (zlib). Ink/Stitch is GPL-3. Running it only on the server has no source obligation, because SaaS is not "conveying". Calling it as a separate CLI process is the lowest-risk way to use it, but compiling or shipping it to browsers would make the client code subject to copyleft. Avoid AGPL code in the service entirely unless counsel signs off. Even unmodified network use carries interpretation risk, and any modification creates an obligation to offer source to every user.

**License mechanics (secondary sources, because gnu.org was unreachable):**
- GPL FAQ, as quoted: "Mere aggregation of two programs means putting them side by side on the same CD-ROM or hard disk"; "Pipes, sockets and command-line arguments are communication mechanisms normally used between two separate programs"; but "intimate communication that exchanges complex internal data structures could be a basis to consider the two parts as combined into a larger program". The FAQ says the line is ultimately a legal question for judges. — [GPL FAQ quoted on EPICS tech-talk](https://epics.anl.gov/tech-talk/2014/msg01688.php); [LWN discussion](https://lwn.net/Articles/999921). Primary source to verify: https://www.gnu.org/licenses/gpl-faq.html#MereAggregation
- Under both GPLv2 and GPLv3, using GPL software to provide SaaS is not distribution or "conveying", so a modified GPL program can run as a public service with a closed fork. — [Black Duck: AGPL / Affero GPL 3](https://www.blackduck.com/blog/agpl-affero-gpl-3.html)
- AGPLv3 §13 ("Remote Network Interaction"): "if you modify the Program, your modified version must prominently offer all users interacting with it remotely through a computer network … an opportunity to receive the Corresponding Source … at no charge." One commentator argues that unmodified deployments generally do not trigger §13. That is an interpretation, not settled law. — [Black Duck](https://www.blackduck.com/blog/agpl-affero-gpl-3.html); [SCL: The Affero GPL](https://www.scl.org/1080-open-source-the-affero-general-public-licence/); [Aber Law Firm: AGPL and SaaS](https://www.aberlawfirm.com/agpl-and-what-every-saas-company-should-know-about-it/)
- LGPL in WebAssembly: there is no authoritative guidance. An OpenCascade developer states that the LGPL "has no exceptions for WASM" and that a closed web app must still offer a way to relink with another library version. Suggested workarounds are a separately loaded module or a commercial license. Forum posts repeat that static linking of LGPL code requires providing relinkable object files. — [OpenCascade forum](https://dev.opencascade.org/content/viewer-webassembly-and-static-linking-single-webassembly); [Qt forum](https://forum.qt.io/post/318067); [Bun licensing docs (LGPL JavaScriptCore relink procedure)](https://bun.com/docs/project/licensing)

### Inferences
Summary matrix (my synthesis from the license texts above; counsel should confirm):

| License | (a) Server-only SaaS | (b) JS/WASM sent to browser = distribution | (c) GPL tool invoked as separate CLI process |
|---|---|---|---|
| MIT (pyembroidery, pystitch, purebyuu) | No obligations triggered | Keep the copyright and permission notice in the shipped bundle (for example a third-party-notices file or a preserved comment banner; minifiers strip comments by default) | n/a |
| BSD-2/3 | No obligations | Keep the notice. BSD-3 also bars using the authors' names to endorse | n/a |
| zlib (libembroidery, Embroidermodder) | No obligations | Do not claim authorship. Mark modified versions. The notice must stay in source distributions; for a binary/WASM-only distribution, acknowledgment is "appreciated but not required" | n/a |
| LGPL-2.1/3 | No obligations | Must allow the user to replace or relink the LGPL part. That is hard with a single statically linked .wasm, so load it as a separate module and ship its source or offer to provide it | n/a |
| GPL-2/3 (Ink/Stitch) | No obligations, even if modified (the "SaaS loophole") | Any GPL code shipped to the browser (transpiled JS or WASM) is conveyance. The combined client bundle would have to be offered under the GPL with source | A separate executable exchanging files (for example PES in, SVG/DST out) via command line or pipes is usually "mere aggregation" (FSF view). Risk rises if it exchanges complex internal data structures or is tightly coupled. If EEganizer never distributes the binary (it runs only on EEganizer's servers), there is no conveyance at all |
| AGPL-3 | Modifying it requires offering Corresponding Source to all network users. Unmodified use is lower risk but debated | Same as GPL, plus §13 | Process separation is not a reliable shield under §13 interpretations. Avoid |

- Practical recommendation (inference): base the server-side parsing, conversion and resizing on pyembroidery or pystitch (MIT), with libembroidery (zlib) as a C/WASM option for in-browser preview. Both licenses allow closed-source commercial use with attribution only. Keep a `THIRD_PARTY_NOTICES` file and include it in any browser bundle.
- Ink/Stitch is a digitizing extension for Inkscape (itself GPL), not a library. EEganizer gains little by embedding it, and the format I/O it needs is already in MIT pystitch. If any Ink/Stitch functionality were ever needed (for example its stitch-plan rendering), run it server-side as a separate process, never in the browser.
- A pyembroidery port to JS/WASM (for example running pyembroidery under Pyodide in the browser) would remain MIT. That is low risk if the notices travel with the bundle.
- MIT/zlib licenses carry no patent grant (unlike Apache-2.0). This is a residual risk to note for counsel, though no embroidery-format patent assertions were found.

### Gaps
- Could not fetch the gnu.org GPL FAQ directly. The quotes come from secondary reposts; verify against https://www.gnu.org/licenses/gpl-faq.html (#MereAggregation, #UnreleasedMods, #GPLInProprietarySystem).
- Did not confirm whether Ink/Stitch's code headers say "GPL-3.0-only" or "GPL-3.0-or-later" (only the LICENSE file's top lines were verified), and did not confirm the licenses of all bundled Ink/Stitch dependencies.

## Q2. Competing and adjacent cloud products for embroidery file viewing, conversion, resizing and organizing

### Takeaway
The main cloud design-library products come from machine and software vendors: Wilcom Workspace Library (browser-based, 10 GB included), mySewnet Cloud/Vault (SVP: Singer/Husqvarna/Pfaff) and Brother Artspira (about 20 free cloud files, about 100 with Artspira+). Each is tied to its own ecosystem. Independent organizers (Hatch Organizer, Embrilliance, StitchBuddy) are mostly desktop or mobile apps with one-time licenses, and pure online converters are thin, free tools. No vendor-neutral, cloud-first library organizer for home embroiderers was found. That is a possible gap EEganizer could fill, though the competitor set is incomplete (see Gaps).

### Cited Findings
- **Wilcom Workspace Library:** "a secure, cloud-based embroidery design management system built specifically for embroidery businesses and teams". The base licence includes 10 GB of cloud storage. It is browser-based with no installation. Data is kept 90 days after cancellation, then permanently deleted. The separate Design Explorer browses local or network folders. Price is on Wilcom's licensing page (not retrieved). — [Wilcom Workspace Library](https://wilcom.com/workspace/library); [Wilcom blog: Library FAQs](https://wilcom.com/resources/blog/library-faqs); [Wilcom blog: 10 key library features](https://wilcom.com/resources/blog/embroidery-design-management-10-key-library-features) (search-result excerpts; the site was not directly fetchable)
- **mySewnet (SVP Worldwide: Singer, Husqvarna Viking, Pfaff):** three subscription tiers (Silver, Gold, Platinum) plus a one-time purchase option. mySewnet Cloud has 100 MB of storage. "Vault" lets users build their own design library organized into Albums. The subscription library has more than 9,000 designs, which are encrypted and checked against an active subscription before stitching, while purchased designs are "yours to keep". Free-trial length conflicts (90 days on one Singer page, 30 days on another). — [mySewnet one purchase](https://mysewnet.com/products-and-plans/one-purchase); [mySewnet Crafting in Library](https://www.mySewnet.com/en-us/crafting/crafting-in-library); [Singer help: What is mySewnet](https://mxhelp.singer.com/en-US/what-is-mysewnet-722408); [Apparel Resources: SVP cloud subscription launch](https://apparelresources.com/technology-news/manufacturing-tech/svp-worldwide-introduces-worlds-first-cloud-subscription-service-embroidery-editing-design-streaming/)
- **Brother Artspira / Artspira+:** the free app has about 20 cloud files, and Artspira+ raises that to about 100. Artspira+ adds auto-digitizing, drawing tools and an Artist Series of embroidery files. Launch price was US$12.99/month (Oct 2023 press release). A later third-party guide claims $4.99/month or $49.99/year, a conflict that remains unresolved. Brother's support page doesn't state a price. — [Brother Artspira plan page](https://support.brother.com/g/s/hf/mobileapp_info/artspira/plan/en.html); [Brother press release via Seeking Alpha](https://seekingalpha.com/pr/19482627-brother-expands-inspiration-with-the-introduction-of-artspira-a-subscription-plan-offering); [App Store listing](https://apps.apple.com/us/app/brother-artspira/id1590796710)
- **Hatch Embroidery (Wilcom-owned consumer brand), including Organizer:** sold as a one-time license with "no ongoing subscription fee". Composer is US$699 one-time. FlexPay offers 13 monthly payments of $99 for Composer/Digitizer. Organizer pricing varies by source ($149 per Techjockey, $199 per a Russian reseller), and no official figure was found. There is no evidence of a cloud component; it appears to be a desktop organizer. — [Hatch pricing](https://www.hatchembroidery.com/pricing); [Hatch pricing policy](https://support.hatch.team/en/articles/9398595-what-is-hatch-s-pricing-policy); [Hatch Organizer 3 overview](https://hatchembroidery.com/videos/hatch-embroidery-organizer-3-overview); [Techjockey](https://www.techjockey.com/detail/hatch-embroidery)

Thumbnailer (shows embroidery thumbnails in Windows Explorer and Mac Finder) is about $39 on sale. No web or cloud product was found. — [Embrilliance software category](https://embrilliance.com/product-category/embrilliance-software); [Embrilliance Thumbnailer](https://www.embrilliance.com/thumbnailer); [Embrilliance brand page](https://embrilliance.com/brand/briton-leap-inc)

It previews and edits down to the stitch level (rotate, resize, recolor, center in hoop), converts formats and syncs via iCloud. It reads JEF, JEF+, JPX, SEW, PES, PEC, EXP, DST, VP3, KSM, PCS, PCQ and PCD, and writes JEF, PES v1, PEC, EXP, DST and PCS. The unlock price was not found. — [App Store StitchBuddy HD](https://apps.apple.com/us/app/-/id522499369); [AppFollow listing](https://apps.appfollow.io/ios/stitchbuddy-hd/522499369?country=us)
- **Embroidery Viewer and Converter (Google Workspace add-on):** free. It views PES, DST, EXP, JEF, VP3, U01 and PEC from local files, a URL, Google Drive, Dropbox or Box, and converts between formats. The listing was last updated in 2022. - **Bernina:** ART is Bernina's native V9 format, and EMB and JAN are also supported. No Bernina cloud library product was found. — [Bernina software help: embroidery files](https://softwarehelp.bernina.com/en/MainHelp/PART_Basics/assets/assets-2.htm)

### Inferences
- The vendor clouds (Wilcom, SVP mySewnet, Brother Artspira) are designed around lock-in: small storage quotas for consumers (Artspira's 20/100 files, mySewnet's 100 MB), encrypted subscription designs and native formats. A vendor-neutral, high-capacity organizer that previews and converts across brands is differentiated against them.
- Wilcom Workspace Library (10 GB, browser-based) is the closest functional competitor, but it targets businesses and teams.
- Hobbyist organizers (Hatch Organizer, Embrilliance, Embird) are desktop and one-time-license, which fits EEganizer's positioning as the cloud alternative.
- Free online converters commoditize basic conversion. EEganizer should treat conversion and resizing as a feature of the library, not as the product.

Each needs a direct check.

- The technology stacks behind competitor products were not found in public sources (the Google add-on's possible use of pyembroidery is an inference).
- "Embroidery Library" (emblibrary.com) cloud features were not found in searches.

## Q3. Commercial SDKs and APIs for embroidery files that could be licensed instead

### Takeaway
Wilcom's Embroidery Web API (EWA) is the clearly documented commercial option. It is a cloud REST/XML API for rendering (TrueView), editing EMB files (text and colors), auto-digitizing and converting to machine formats (DST, PES, EXP and others). Access requires an App ID/App Key under a subscription plan from Wilcom's developer portal. Pricing is not public. No public pricing or SDK was found for Pulse Microsystems.

### Cited Findings
- Wilcom EWA is a cloud-hosted, RESTful, XML-based API to "integrate professional embroidery design and personalization features into websites, e-commerce platforms, or internal systems", covering rendering, editing, auto-digitizing and file conversion. — [Wilcom Embroidery API KB](https://help.wilcom.com/portal/en/kb/wilcom-international/embroidery-api); [EWA product description](https://help.wilcom.com/portal/de/kb/wilcom-international/embroidery-web-api); [API Interface Specification](https://apiguide.wilcom.com/documents/api-interface-specification/)
- Access requires company registration, an API plan selection, and App ID/App Key credentials issued on subscription via the developer portal (developer.wilcom.com). — [EWA getting started](https://help.wilcom.com/portal/en/kb/articles/ewa-api-getting-started)
- EWA centers on the EMB format, with machine outputs such as DST, PES and EXP. Most functions modify parts of an EMB file (text, thread colors). For production it needs machine-specific extensions (for example DST for Tajima, TAP for Happy). Lettering uses Wilcom ESA fonts, not TTF/OTF. — [EWA technical notes](https://help.wilcom.com/portal/en/kb/articles/ewa-api-technical-notes); [Supported file formats](https://help.wilcom.com/portal/en/kb/articles/supported-formats)
- Wilcom warns that auto-digitizing results may not match expectations and advises filtering unsuitable images. — [EWA technical notes](https://help.wilcom.com/portal/en/kb/articles/ewa-api-technical-notes)
- Wilcom publishes an EWA "business case" article (content not retrievable this session). — [EWA API business case](https://help.wilcom.com/portal/en/kb/articles/business-case)

### Inferences
- EWA solves a different problem (personalization and e-commerce rendering of EMB designs) and would add per-call cost and vendor dependency. For EEganizer's needs (preview, convert and resize customer-owned machine files), the MIT and zlib libraries already cover the formats in common use. EWA would mainly add value for high-fidelity TrueView renders or object-based resizing (re-computing stitch density), which stitch-level libraries cannot do well. Plain scaling of stitch files without re-digitizing changes density; this is a known limit of stitch-format resizing.
- Licensing a commercial API carries contract terms (data handling, rate limits, branding) that need review alongside the privacy commitments EEganizer makes to its customers.

### Gaps
- No public pricing or plan tiers for Wilcom EWA.
- No information found on a Pulse Microsystems (Tajima Pulse) SDK, or on other commercial conversion APIs. These need direct vendor inquiry.
- Whether Wilcom's API terms allow processing third-party (customer-purchased) designs at scale is not verified.

## Q4. Legal and IP concerns: converting purchased designs, and reverse engineering proprietary formats (Bernina ART, Husqvarna HUS)

### Takeaway
Designer licenses vary. Sharing or redistributing design files is consistently prohibited, but format conversion is permitted by some sellers (for example Creative Fabrica, "for your own use") and silent or restricted at others. EEganizer should convert only for the account owner's own use, never expose files publicly or across accounts, and put that in its terms of service. Reading proprietary formats via independently developed open-source parsers is generally supported by interoperability exceptions in the US (17 U.S.C. 1201(f) and Sega v. Accolade fair use) and the EU (Software Directive Art. 6). But circumventing encryption, such as on mySewnet subscription designs or any encrypted ART, is a DMCA §1201 risk that needs counsel.

### Cited Findings
- Urban Threads: the license allows stitching for personal use and small-scale sales. The design file itself can't be sold or shared, and copyright stays with Urban Threads (excerpt only; the full policy's position on conversion was not seen). — [Urban Threads design page](https://urbanthreads.com/design/sku/ESP85856-5)
- Creative Appliques: sharing, copying, trading or reselling the design "in whole or part, in any format" is barred. — [Creative Appliques](https://creativeappliques.com/?p=240337)
- Creative Fabrica: the license explicitly lets a buyer convert a needlework file to another needlework format for their own use, but bars selling or sharing unstitched versions. — [Creative Fabrica Single Sales License](https://creativefabrica.com/de/single-sales-license)
- Some Etsy embroidery sellers permit copies only for personal backup or archival purposes and bar using parts of designs to make other files. — [Etsy listing](https://www.etsy.com/listing/1404279012/embroidery-digitizing-license-commercial); [Ignite Wonder policy](https://ignitewonder.patternbyetsy.com/policy)
- mySewnet subscription-library designs are encrypted and require an active subscription to stitch. — [mySewnet Crafting in Library](https://www.mySewnet.com/en-us/crafting/crafting-in-library)
- pyembroidery reads Husqvarna .HUS (and Pfaff VP3) but does not list Bernina .ART. — [pyembroidery README](https://raw.githubusercontent.com/EmbroidePy/pyembroidery/master/README.md)
- ART is a Bernina design format (ARTlink, and the native format of Bernina V9) that contains objects, outlines, stitch data, thread colors and settings. Whether it is encrypted was not confirmed in public sources found. — [fileformat.com ART](https://docs.fileformat.com/misc/art); [Bernina help](https://softwarehelp.bernina.com/en/MainHelp/PART_Basics/assets/assets-2.htm)
- 17 U.S.C. 1201(f) lets a lawful user of a program circumvent access controls to identify the elements needed for interoperability, where not previously readily available. Critics note courts have read it narrowly, which may not cover decoding of file formats per se. Sega v. Accolade (9th Cir.) held disassembly for interoperability to be fair use. — [17 U.S.C. §1201 (govinfo)](https://www.govinfo.gov/content/pkg/USCODE-2024-title17/html/USCODE-2024-title17-chap12-sec1201.htm); [Project DISCO on interoperability and §1201](https://project-disco.org/intellectual-property/070617-interoperability-and-the-copyright-offices-section-1201-report/); [Perzanowski, UC Davis L. Rev. on interoperability](https://www.perzanow.ski/s/UC-DavisLR-Interop.pdf)
- EU Directive 2009/24/EC Art. 6 allows reproduction or translation of code when indispensable to obtain interoperability information, by a lawful user, where the information is not readily available. The CJEU (C-13/20 Top System) read Art. 6 as applying only where interoperability cannot be achieved otherwise. — [Directive 2009/24/EC Art. 6](https://www.legislation.gov.uk/eudr/2009/24/article/6); [Cuatrecasas on Top System](https://www.cuatrecasas.com/en/spain/article/decompilation-of-software-for-error-correction-cjeu-judgment-in-top-system)

### Inferences
- Using an existing, independently developed open-source parser (pyembroidery reading HUS) is lower risk for EEganizer than doing its own reverse engineering. Plain file-format parsing of an unencrypted file is generally not a §1201 issue, because no technological measure is circumvented. Counsel should confirm this.
- Hard line (inference): EEganizer should not decrypt or strip DRM from encrypted vendor-library designs (mySewnet subscription designs, or any encrypted ART). It should detect such files and store them as opaque blobs with "preview unavailable".
- Converting a customer-purchased design for the customer's own machine is plausibly within many licenses but not all. Mitigations: per-account private storage only, no sharing or public links for converted outputs, a ToS clause that the user warrants they hold the rights to upload and convert, and a DMCA takedown process (and DMCA agent registration in the US). All of these need counsel.
- Hosting user-uploaded copyrighted designs also implicates DMCA §512 safe harbor. This was not researched here but should go to counsel.

### Gaps
- No authoritative public documentation on whether Bernina .ART (V5-V9) or Husqvarna/mySewnet .VP4/.VIP files are encrypted or obfuscated.
- No case law found specifically on embroidery-format conversion or embroidery DRM.
- Embroidery Library (emblibrary.com), Anita Goodesign, OESD and other major designers' license wording on format conversion was not retrieved.
